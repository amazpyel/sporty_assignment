# Single Bet Placement Feature Test Plan
This  test plan covers the most prioritized test scenarious for the desktop web application that simulates a sports betting flow.

## Test scenarious
| Test Case ID | Title | Priority | Risk Rationale | Steps | Expected Result |
|---|---|---|---|---|---|
| **TCSBP-01** | Place valid single bet | **Critical** | This is the core business flow. Failure prevents users from placing bets, while incorrect stake deduction or bet creation can cause direct financial impact. | Preconditions:<br> Call POST /api/reset-balance and record the balance as B0.<br><br> 1. On match M, click the 1 (home) odds button.<br>2. Enter a stake of 10.00.<br>3. Check that the slip shows selection, stake, balance B0 and payout stake x odds EUR.<br>4. Click Place Bet.<br>5. Close the receipt. | Bet is successfully placed. Stake is deducted once. Success receipt is displayed with the required bet information. |
| **TCSBP-02** | Accept maximum permitted stake of 100.00 | **High** | Verifies the upper financial boundary defined by the specification without combining it with the invalid boundary case. | 1. Select an upcoming football match.<br>2. Select a valid outcome.<br>3. Ensure available balance is at least `EUR100.00`.<br>4. Enter `EUR100.00`.<br>5. Click **Place Bet**. | Stake is accepted and the bet is successfully placed. Exactly `EUR100.00` is deducted. |
| **TCSBP-03** | Reject stake exceeding maximum by EUR0.01 | **High** | Protects the maximum wagering limit. Acceptance of a value immediately above the permitted boundary could allow users to exceed the configured per-bet limit. | 1. Select an upcoming football match.<br>2. Select a valid outcome.<br>3. Enter `EUR100.01`.<br>4. Attempt to place the bet. | Bet is rejected with the maximum-stake validation. No bet is created and no balance is deducted. |
| **TCSBP-04** | Reject stake exceeding available balance | **Critical** | A failure of the balance constraint could result in a user wagering more than available funds and creates direct financial-integrity risk. | 1. Reset available balance.<br>2. Select an upcoming football match.<br>3. Select a valid outcome.<br>4. Enter `EUR125.01`.<br>5. Attempt to place the bet. | Bet is rejected with **Insufficient balance**. No bet is created and no money is deducted. |
| **TCSBP-05** | Concurrent duplicate submission is rejected with 409 | **High** | Double-clicks, multiple tabs or network retries can submit in parallel. The UI loading state does not protect the API, and a missing 409 means a double charge. | 1. Send two parallel POST /api/place-bet requests with the same x-user-id and body {matchId: M, selection: "DRAW", stake: 10}.<br>2. Call GET /api/balance. | One request returns 200 and the other returns 409. Only one bet is placed. The balance is deducted by 10 EUR |
