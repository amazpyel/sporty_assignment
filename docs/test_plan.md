# Single Bet Placement Feature Test Plan
This  test plan covers the most prioritized test scenarious for the desktop web application that simulates a sports betting flow.

## Test scenarios

| Test Case ID | Title | Priority | Risk Rationale | Steps | Expected Result |
|---|---|---|---|---|---|
| **TCSBP-01** | Place valid single bet | **Critical** | This is the core business flow. Failure prevents users from placing bets, while incorrect stake deduction, payout or receipt data causes direct financial impact and customer disputes. | Preconditions:<br>Call POST /api/reset-balance, then GET /api/balance and record the balance as B0.<br><br>1. On match M, click the 1 (home) odds button and note the odds O.<br>2. Enter a stake of `10.00`.<br>3. Check that the slip shows the selection, stake, balance B0 and payout 10.00 × O.<br>4. Click **Place Bet**.<br>5. Close the receipt. | The button shows **Placing...** and then succeeds.<br>The receipt shows Bet ID, match (home vs away), selection, stake €10.00, odds O, payout €10.00 × O and a timestamp.<br>After closing, the slip is empty and the balance is **B0 − €10.00**. |
| **TCSBP-02** | Accept maximum permitted stake of €100.00 | **Medium** | Verifies the upper valid boundary. A failure blocks legitimate max-stake bets (lost revenue) but creates no financial exposure. | Preconditions:<br>Call POST /api/reset-balance, then GET /api/balance and record the balance as B0 (≥ €100.00).<br><br>1. Select an upcoming match and a valid outcome.<br>2. Enter `100.00` as stake.<br>3. Click **Place Bet**. | No validation message is shown.<br>The bet is placed successfully.<br>The balance is **B0 − €100.00**. |
| **TCSBP-03** | Reject stake exceeding maximum by €0.01 (UI) | **High** | Protects the per-bet wagering limit. Accepting a value just above the boundary lets users exceed the configured limit. | Preconditions:<br>Call POST /api/reset-balance, then GET /api/balance and record the balance as B0.<br><br>1. Select an upcoming match and a valid outcome.<br>2. Enter `100.01` as stake.<br>3. Attempt to place the bet. | The message **Maximum stake is €100.00** is shown.<br>Placement is blocked, and no request is sent.<br>The balance remains **B0**. |
| **TCSBP-04** | Reject stake exceeding available balance by €0.01 (API) | **Critical** | A missing balance check lets users bet funds they don't have, producing a negative balance (unsecured credit gambling). The API must enforce this because the UI can validate against a stale balance. | Preconditions:<br>Call POST /api/reset-balance. Place a €100.00 bet so that the balance is below €100.00. Call GET /api/balance and record it as B.<br><br>1. Send POST /api/place-bet with a valid matchId and selection and `stake: B + 0.01`.<br>2. Call GET /api/balance. | The API returns **422** with an insufficient-balance error.<br>No bet is created.<br>The balance remains **B**. |
| **TCSBP-05** | Reject bet on past match (API) | **Critical** | The spec allows betting on upcoming (pre-match) events only. Accepting bets on past matches lets users bet on known results, guaranteeing wins and causing direct financial loss and betting-integrity breaches. | Preconditions:<br>Call POST /api/reset-balance, then GET /api/balance and record the balance as B0.<br>Call GET /api/matches and identify a match M with kickoffDate before today.<br><br>1. Send POST /api/place-bet with the matchId of M, a valid selection and `stake: 10`.<br>2. Call GET /api/balance.<br><br>Note: the exact error code will be updated after SBP-6 is clarified. | The API rejects the request (non-200).<br>No bet is created.<br>The balance remains **B0**. |
| **TCSBP-06** | Reject stake below minimum (€0.99) (API) | **High** | Protects the lower wagering limit. A missing lower bound also allows zero or negative stakes, which can increase the balance. €0.99 is invalid under either reading of the spec's €1.00/€1.01 conflict. | Preconditions:<br>Call POST /api/reset-balance, then GET /api/balance and record the balance as B0.<br><br>1. Send POST /api/place-bet with a valid matchId and selection and `stake: 0.99`.<br>2. Call GET /api/balance. | The API returns **422** with a minimum-stake error.<br>No bet is created.<br>The balance remains **B0**. |
